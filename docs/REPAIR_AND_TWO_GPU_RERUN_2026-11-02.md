## 修复内容

- 原图任务增加显式编辑计划：每个答案、曲线或高亮都有目标框、步骤和理由。
  校验几何边界与面积后，另一次视觉调用核查任务覆盖、位置和阻挡关系。
  通过的计划编译成逐项执行的 Manim 代码，避免模型注释声称填两项而代码只填一项。
- 只冻结通过计划验收的目标框；非法框不会污染后续重试。Storyboard 拒绝原因回传给下一次规划。
  已验证的框仍禁止扩大。触碰箭头的答案框不再仅靠四边形近似识别。
- 保留完整本地证据，请求只附有界反馈和诊断摘要。使用本地分词器计算文本 token，
  另为图像、模板及输出预留预算，调用前阻止超限；不截断原任务文本。
- 渲染阶段按整数帧执行每个动画和停留，修复 75 帧预算偶尔输出 76 帧的问题。
  源图线宽留边按实际渲染比例计算，原图编码前逐帧保护继续要求授权框外零像素变化。
- 独立示意图在动画结束状态检查文字边界、至少 16 渲染像素及相互重叠，失败进入修复。
  简化原有拥挤的固定网格模板；排序提示要求原数字对象实际交换位置。
- 包含 InChI 的化学题使用 RDKit 解析标识符、生成立体结构和匹配官能团。
  初始结构与分类高亮图由同一分子生成；渲染要求使用两个验证素材，不允许凭空重画替代。
- 评分先生成共享的逐帧可见事实，再进行八轴判断；另一次检查识别实质事实矛盾。
  冲突维度可有界复判一次，仍冲突则评分无效，不让高分抵消矛盾。
- 失败结果保留诊断渲染的真实时长与明确失败阶段，避免把原图保护失败一概写成时长失败。

这些是通用流程修复，没有按十题 ID 写死生成答案或放行名单。

## 两卡重跑方式

额外 CPU 依赖见 `requirements-local-generation.txt`，不修改 vLLM 环境。
检查 GPU 空闲后，使用两个独立 vision 服务；本次保留空闲 GPU 0、1 上端口 8000、8001 的服务，
已停止旧批次由本代理启动的 GPU 2、3 服务。十题由共享队列动态分配，不绑定固定尾部任务。

修复提交推送 main 后，从仓库内保存的同十题列表，在全新目录运行：

```bash
/root/code2video-env/bin/python -u scripts/run_qwen_multigpu.py \
  --gpus 0 1 --ports 8000 8001 \
  --out results/qwen38_two_gpu_sample10_v4_20261102
```

每题最多三次外层尝试，内部修复也有边界。`progress.json` 持续更新；逐题保存
`final_<id>.json`、每次反馈/评分/日志；最终 `completion.json` 与新评分目录保留十题分母。
`execution_finished` 表示运行结束，`complete` 仍要求所有题质量通过。
只有显式 `--resume` 且提交、题目哈希、contract、评分版本完全相同时才能续跑。

本次目标是十题顺利完成并通过验收；最终成功率需以这次新批次的实际结果报告，不能提前承诺。
