## 运行发现与修复

1. 作者顶层资源目录与 src 下的查找路径不一致：建立 src 到顶层 assets、json_files、prompts 的链接。
2. `TeachingVideoAgent.__init__` 引用了全局 `api`：作为模块导入时触发 `NameError`，改为 `self.API`。
3. 渲染子进程未加载已生成代码：离线两片段首次为 0/2；修复为从磁盘恢复代码后为 2/2。
4. 移除入口的明文素材密钥输出。
5. 每段渲染保存 stdout/stderr，保留实际错误供排查。
6. 添加 `local` API 分支，使用独立本地端点配置和 token 统计；输出截断时显式失败。
7. 作者会捕获异常并打印“processed”，因此新试跑脚本检查实际视频、总片段数及覆盖率，不以退出成功文案验收。

首次并发修复后出现过单段失败，独立渲染成功；后续再次并发为 2/2。
未保存最初的渲染 stderr，不能确定该次单段失败原因，也不据此宣称并行稳定性。

首轮四卡 8 题已结束：完整成功 7/8，片段覆盖 36/37；原始结果保存在
`experiments/initial_batch/`。`math_exp_01` 首轮仅 4/5，有部分合片但未计为完整成功。

另发现作者最后一次修复后没有再次渲染验证，已增加一次最终验证渲染，
不增加允许的模型修复次数。真实 Manim 回归检查 `experiments/check_last_fix.py`

## 复现入口

```bash
bash research/code2video/experiments/bootstrap_source.sh
# 在具备上述环境及 GPU 的主机启动，保持终端运行：
bash research/code2video/experiments/start_qwen38.sh
# 另一终端运行：
bash research/code2video/experiments/run_model_case.sh
```

在本会话受限沙箱里，模型服务及客户端使用已批准的沙箱外执行。
依赖、权重和服务不由 bootstrap_source.sh 安装；该脚本只准备固定源码与 patch。
